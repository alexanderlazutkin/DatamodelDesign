## 3. Кандидаты дополнений

**К-14. Выборочные запросы как приём сценарной проверки (к PR-004 / Ж.9.1 п. 14; методическое).**
Валидация модели — тремя способами: вербализация примеров, проверка популяциями, прогон выборочных запросов: «a third way to validate a model is to see whether it enables *sample queries* to be answered… navigate around the ORM model to see if you can answer them. If you can't, your schema is incomplete» (гл. 3.5). Дополняет сценарную проверку CDM-042 техникой «запрос-проба».

**П-15. Подтип — для роли, не для таксономии (прил. Р; усиливает К-2 рецензии 01).**
Подтип вводится, прежде всего, чтобы заявить роль, играемую только им; каждый подтип определяется формально через роли супертипа («each Woman is a Person who is of Sex 'F'»); подтипы без собственной роли не вводятся — классификация выражается типом факта со значением.
Основание: «The main reason for using a subtype in modeling is to *declare a constraint that a specific role is played only by that subtype*»; «Each subtype must be formally defined using one or more roles of its supertype(s)»; анти-пример: «this would lead to almost 200 subtypes in the schema! This is crazy. If one of these subtypes plays a specific role, then we should introduce it; but if it doesn't, we should not do so» (гл. 6.5).

**П-16. Свойства рекурсивных связей (к CDM-029/CDM-020; методическое).**
Проверочный словарь для рекурсивных отношений: иррефлексивность (никто не родитель себе — «no Person is a parent of itself»), симметричность/асимметричность, транзитивность, ацикличность; каждое заявленное свойство фиксируется как правило. Готовые вербализации для текстовых правил вне графики (2.8).

**Заметки:** «snapshot/historical fact type» — рабочие термины к LDM-040/042; декомпозиция «exactly one = at least one + at most one» для спецификаций связей; частотные ограничения (n, ≥n, n..m, составные) — текстовые правила к CDM-015; «derived and stored» с триггером — конкретизация К-11; относительность идентификации к охвату при объединении подмоделей (4.7) — пример University subject; таксономия set-comparison ограничений — для [Заполняется] прил. С.

**Термины:** в словарь не вводятся (совпадения с T-016…T-029 покрывают; «снимок» уже есть — T-044 периодический снимок).

## 4. Конфликты и осознанные ограничения

- **Конфликтов не выявлено.** Строгость ORM выше нейтральных норм Правил (обязательные формальные определения подтипов; запрет таксономических подтипов) — принимается как методика (П-15), без повышения модальностей CDM-027.
- **Терминология:** «external level» Halpin (доступ групп) ≠ что-либо в Правилах — покрывается «представлением» (T-006) и профилем публикации (11.10); не вводится.
- **Вне охвата (осознанные):** гл. 8–9 — сравнение нотаций (перечень — прил. В, решение Р-010); гл. 10–11 — реляционное отображение и SQL (реализация); гл. 12 — механика трансформаций (суть покрывает LDM-032); гл. 13 — DW/OLAP/мета-моделирование (профили/3.11).

## 5. Резюме

**Оценка влияния:** высокая методическая, нулевая нормативная. Самый строгий источник серии: формальная вербализация всех ограничений — прямой фундамент правила тройного соответствия (2.8) и спецификаций связей; уникальные вклады — дисциплина подтипизации (П-15), свойства рекурсивных связей (П-16), выборочные запросы (К-14), относительность идентификации к охвату.

**Приоритеты:** П-15 (подтип для роли; усиливает К-2 вместе с П-8/П-12) — высокий; К-14, П-16 — средний; заметки — низкий.

**Открытые вопросы для человека:** включать ли «формальное определение подтипа» (вербализация через роли супертипа) как обязательный элемент чек-листа Ж.9.1 п. 7 при lit-001 (сейчас CDM-027 требует «критерий принадлежности» — формулировка Halpin строже, но совместима).
