## 3. Кандидаты дополнений

**К-5. Методика сопоставления «подзадача → паттерн» (методическое наполнение прил. М.2, между п. 2 и 3; без новой нормы).**
Шаги: (1) разбить согласованный охват на функциональные подзадачи; (2) искать кандидатов-паттернов тремя эвристиками — буквальное подобие (сущность подзадачи — подтип/синоним сущности паттерна), абстракция (отношение подзадачи — частный случай отношения паттерна), аналогия (параллель отношений при несходных сущностях); (3) сопоставить конструкты 1:1 с фиксацией неточностей и статусом уверенности по T-037.
Основание: «STEP #1: Identify sub-tasks in the task description… STEP #2: Compare sub-tasks with patterns… STEP #3… the user will attempt to create a one-to-one mapping between constructs in the sub-task and the constructs in the pattern… will note instances where the mapping is not exact. In addition, the user will rate his/her confidence on the accuracy of each mapping»; «abstraction is to relations as literal similarity is to entities» (разд. Steps 1–3).

**К-6. Чек-лист верификации применимости паттерна (прил. М, дополнение к п. 2–3).**
Поверхностная оценка → глубокая проверка по трём осям (атрибуты, сущности, связи) → фиксация различий → разрешение каждого различия (принять/адаптировать/отказ) → признание применимости/неприменимости → финальная верификация по всей подзадаче.
Основание (Appendix, коды 4–8): «Evaluating a pattern for task involves making surface level mappings…; Verifying correctness of pattern to task includes making deeper level comparisons between attributes, entities, and relationships required in the task with those provided by the pattern; …Identify differences; Resolve differences; Recognize applicability / inapplicability; Final Verification».

**К-7. Перечень типовых паттернов (наполнение [Заполняется] М.4/Р — после консолидации с рецензиями 06, 08–10).**
Одиннадцать классов статьи как стартовая сетка рубрик: people; organization; accounts; planning/monitoring; transactions/delivery of goods; assets/ownership; membership/employment; work orders; time-related concepts; portfolio; projects.
Основание: «Some of the commonly occurring patterns, and the entities they use are listed in the table below. They have been compiled from Hay (1996), Silverstone et al (1997), and Fowler(1997)» (Table 1).

**Термины:** «подзадача (sub-task)» и «паттерн (data model pattern)» — рабочие термины для прил. М/Р; в словарь не вводятся (паттерн уже используется прил. Р; «референтная модель» — М.1). «Структурное отображение (structure mapping)» — теоретическая основа, в комплект не переносится.
