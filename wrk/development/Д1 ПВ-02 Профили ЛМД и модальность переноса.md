# Д1: материалы решения ПВ-02 — профили ЛМД и модальность переноса

**Версия:** 0.1, 2026-10-10. **Статус:** проект материалов к решению; решения утверждает методолог/архитектор данных (план 0.4, § 3, ПВ-02). Уровень — инициативный до решения ПВ-01.
**Основание:** план 0.4, § 3 (ПВ-02), § 4 (Д1); С01 v0.8 — 2.4, 3.5, 3.6, 3.10, прил. А, Б; С03 (`LDM-009…015`, `LDM-018`, `LDM-021`, `LDM-027`, `LDM-032`); С04 — обозначения областей `ЛМД` / `ЛМД-Р`; Р-004 (таблица Б5).
**Ограничение:** новые ID и способ записи требований назначаются на Д3; здесь фиксируются только принцип применимости и варианты решения.

## 1. Суть вопроса

Требования С03 используют реляционные понятия (PK, FK, идентифицирующая связь, ассоциативная сущность, нормальные формы) как универсальные для всей ЛМД. С01 2.4 определяет профили моделирования (корпоративная интеграционная, системная реляционная, аналитическая, документная/полуструктурированная), а С04 прямо ограничивает PK/FK/кандидатный ключ/нормализацию областью `ЛМД-Р`. Условие закрытия ПВ-02: **PK/FK, разрешение M:M и нормализация не распространены безусловно на все профили; повышение рекомендации оформлено решением**.

## 2. Что говорят источники

- С01, 2.4: основная область применения профилей — ЛМД; для каждого профиля устанавливаются применимые конструкции (прил. Б); конфликт профилей разрешает архитектор данных с фиксацией в реестре решений.
- С04, обозначения областей: «Требования реляционного профиля не переносятся автоматически на документные и полуструктурированные модели». PK — `ЛМД-Р; ФМД-Р`; FK — `ЛМД-Р; ФМД-Р`; кандидатный ключ — `ЛМД-Р`; нормализация — `ЛМД-Р`; идентификатор, кардинальность, обязательность участия — `КМД; ЛМД` (общие); обоснованная избыточность — `ЛМД; ФМД`.
- С03: модальности по исходнику — `LDM-009`, `LDM-011`, `LDM-012`, `LDM-013`, `LDM-014`, `LDM-015` — ОБЯЗАТЕЛЬНО; `LDM-010`, `LDM-018`, `LDM-021`, `LDM-027`, `LDM-032` — РЕКОМЕНДУЕТСЯ (см. разд. 3).

## 3. Построчный разбор применимости (предложение)

Обозначения: «общ.» — применимо ко всем профилям ЛМД; «ЛМД-Р» — реляционный профиль (или реляционный фрагмент составной модели, С01 2.4).

| ID | Исходная модальность | Общая часть (все профили) | Реляционная часть (ЛМД-Р) | Предложение |
|---|---|---|---|---|
| LDM-009 | ОБЯЗАТЕЛЬНО | основной и альтернативные идентификаторы; однозначность в области; минимальность; обязательность атрибутов составного идентификатора | выбор PK; запрет NULL в компонентах ключа | Одна запись с профильной оговоркой либо разделение на общее + реляционное (по тесту 3.10, на Д3) |
| LDM-010 | РЕКОМЕНДУЕТСЯ | простой идентификатор по умолчанию; обоснование составного | суррогатный ключ как способ | Все профили; реляционные термины — пример реализации |
| LDM-011 | ОБЯЗАТЕЛЬНО | смысл связи и роль; допустимость отсутствия связанного экземпляра | логический FK; идентифицирующая связь (наследование идентификатора в PK) | Кандидат на разделение: общее обязательство смысла связи + реляционное обязательство ссылочной реализации |

| LDM-018 | РЕКОМЕНДУЕТСЯ | обязательность участия (понятие) | обязательность FK по умолчанию; nullable-свойства; составные FK | Понятие — общее (С04); FK-механика — ЛМД-Р |

| LDM-032 | РЕКОМЕНДУЕТСЯ | обоснованная избыточность; правила согласованности копий | нормальные формы | Избыточность — все профили; НФ — ЛМД-Р |

## 4. Варианты решения

**Вариант А (рекомендуется): профильная разметка при переносе.** При переносе на Д3 каждому требованию назначается применимость по таблице разд. 3; требования со смешанной нагрузкой (009, 011, 015, 018, 021, 032) либо сохраняют один ID с явной профильной оговоркой, либо разделяются на общую и профильную части по тесту атомарности 3.10 (новые ID + связи преемственности) — построчно на Д3. Нормативное правило для разд. 7/прил. Б: «понятия PK/FK, кандидатный ключ, нормализация применяются в реляционном профиле; для остальных профилей применимость задаётся прил. Б; отсутствие профильной записи не создаёт обязательства».
Плюсы: минимальная переработка исходников; прямое соответствие С01 2.4 и С04; проверяемость. Минусы: требует дисциплины построчных решений на Д3.

**Вариант Б: С03 целиком — реляционный профиль.** Все требования С03 переносятся с применимостью ЛМД-Р; общий слой создаётся заново.
Минусы: универсальные требования (LDM-013, LDM-027) ошибочно сужаются; дублирование будущего общего слоя.

**Вариант В: сплошная профильно-нейтральная переработка.** Все требования переписываются без реляционных терминов; детали — в прил. Б.
Минусы: большая переработка, риск потери точности исходников; противоречит минимальному характеру переноса (Р-003, Б1–Б5).

## 5. Модальность переноса

- Перенос — по таблице Б5 (Р-004) без изменений модальности: ОБЯЗАТЕЛЬНО → `required`, РЕКОМЕНДУЕТСЯ → `recommended`.
- `LDM-027` (домены), `LDM-010`, `LDM-018`, `LDM-021`, `LDM-032` переносятся как `recommended`. Повышение модальности любого из них — отдельное решение методолога с записью в реестре решений, не часть переноса (условие ПВ-02).
- Примеры повышения, требующие отдельного решения (не предлагаются, только фиксируются как возможные): LDM-027 → `required` для новых моделей; LDM-032 → `required` для реляционного профиля.

## 6. Влияние на пилотный срез (план 0.4, § 7.1)

- `LDM-009` входит в срез (группа «определение, гранулярность и идентичность»); применимость в пилоте определяется профилем объекта ПВ-09. Ожидаемый объект — фрагмент системной ЛМД реляционного типа → применяется полная запись (общая + реляционная части).
- `LDM-023/LDM-027` (типы и домены) — применимость всех профилей, в срезе без ограничений.
