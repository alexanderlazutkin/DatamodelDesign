# Приложение С. Матрица реализации ограничений

**Версия:** 0.6-лит1 (Р-054: добавлен раздел С.5 «Обоснованная избыточность — методика сопровождения» — К-11, review/05/07/12). Прежние события: 0.5-в3 (волна 3 Д7). Статус — рабочий документ (форма); наполнение строк — по мере документирования моделей.

## С.1. Назначение

Матрица — сводная форма 8.9: для каждого значимого бизнес-правила фиксируются раздельно логическое правило, результат преобразования, механизм реализации, состояние реализации, способ проверки и ограничения реализации. Назначение механизма контроля не означает выполнения требования; матрица не заменяет записи проверки ([[А Каталог требований и схема записей проверки#А.8. Запись результата проверки соответствия|прил. А.8]]) и свидетельства ([[Г Минимальные метаданные|прил. Г]]).

## С.2. Структура строки

| Колонка | Содержание | Основание |
|---|---|---|
| Правило | Формулировка бизнес-правила (6.13, LDM-021) | 8.9 |
| Результат преобразования | Сохранено / изменено по решению / не представлено | 8.8 |
| Механизм реализации | Физически объявленное ограничение / контроль приложения / контроль загрузки / отдельная проверка | 8.9, 9.6 |
| Состояние реализации | Реализовано / частично / запланировано / не реализовано / не установлено | 8.9 |
| Ответственный компонент | Система/модуль | 8.9 |
| Способ проверки | Процедура и свидетельства | 8.9, прил. Г |
| Ограничения реализации | Известные ограничения | 8.9 |

## С.4. Правила ведения

Строки связываются с элементами моделей и записями реестра вопросов (4.8); при AS-IS матрица фиксирует фактическое состояние без обязанности устранения (9.6, 10.5). Форма машиночитаемого ведения — при включении в реестр (3.11).

## С.5. Обоснованная избыточность — методика сопровождения (LDM-032, T-025; Р-054 — К-11, review/05/07/12)

Методика выбора и сопровождения отклонений от нормализации (обязательства — по LDM-032; раздел методический):

1. **Критерий выбора — волатильность.** Избыточность концентрируется на редко изменяемых данных; для волатильных данных оценивается цена поддержки согласованности при каждом изменении («you are better off concentrating denormalization on nonvolatile fields», review/05). Для чисто читаемых аналитических хранилищ риск рассинхронизации ниже (профиль нагрузки).
2. **Приёмы с обязательным правилом согласованности.** Сводная колонка (агрегат) — с механизмом синхронизации при изменениях источников (триггер/процесс, включая события сброса, например годовое обнуление накопителей); предагрегация для частых агрегирующих запросов — аналогично.
3. **Альтернатива структурной денормализации** — предварительно соединённые представления (materialized view / снапшот): выровненное представление без изменения структуры хранения; при выборе фиксируется правило обновления снапшота.
4. **Производные атрибуты.** Выбор «вычислять при чтении» либо «вычислять и хранить» (derived and stored, review/07) — способ реализации (T-038); при хранении действует п. 2. Производные атрибуты не создают аномалий обновления, если не вводятся вручную и не служат ключами (review/12).
5. **Ответственность.** Для каждой позиции избыточности фиксируются: основание (профиль нагрузки), правило согласованности, механизм и состояние реализации (строкой С.2); осознанная избыточность адресного текста (например, дублирование частей адреса при иерархии локаций) допускается с ответственностью бизнеса (review/06).
