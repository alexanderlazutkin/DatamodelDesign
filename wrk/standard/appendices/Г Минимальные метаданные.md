# Приложение Г. Минимальные метаданные

**Версия:** 0.3-в1 (волна 1 Д7, рабочая редакция стандарта 0.3). Статус — рабочий документ; состав полей может расширяться, но не сокращается относительно настоящего приложения.

## Г.1. Назначение и общие правила

Приложение определяет минимальный обязательный состав метаданных моделей, представлений, элементов и связанных записей. Метаданные хранятся как метаданные модели в авторитетном хранилище (3.11, 11.1); отдельные файлы карточек не обязательны. Формат ведения — структурированный (репозиторий инструмента либо текстовый формат, 3.11); при включении связанных записей в реестр они ведутся в машиночитаемой форме.

## Г.2. Паспорт модели

Обязательные поля:

| Поле | Содержание | Основание |
|---|---|---|
| Идентификатор модели | Стабильный ID в пространстве имён (11.2) | 11.2 |
| Назначение | Для чего модель создана и применяется | CDM-001, LDM-028 |
| Уровень и вид | КМД/ЛМД; вид по назначению и охвату (2.3) | 2.2–2.3 |
| Профиль(и) | Профили моделирования; для КМД — решение о применении профиля | 2.4 |
| Режим и состояние | TO-BE / AS-IS / смешанный (3.1–3.3); состояния фрагментов | 3.4 |
| Домен | Бизнес-домен; для ЛМД — система либо домен | CDM-001, LDM-028 |
| Контекст | Организационный и процессный контекст | CDM-001 |
| Охват и исключения | Согласованные границы (5.2) | 5.2 |
| Версия и статус | По статусной модели 11.9 | 11.9 |
| Ответственные | Владелец модели и иные роли (4.1) | 4.1 |
| Базовая версия | Для рабочих версий и пакетов изменений | 4.6 |
| Хранилище | Авторитетное хранилище; порядок работы с копиями | 11.1 |
| Дата актуальности | Дата и история изменений паспорта | 11.9 |

Паспорт создаётся до начала работ (этап 2, 5.1) и актуализируется при смене статуса (11.9).

## Г.3. Паспорт представления

Обязательные поля (11.4): назначение; аудитория; охват; версия; уровень детализации; скрытые категории элементов. Публикация представления — по профилю публикации (11.10); скрытие пометки ИОД на представлении не изменяет метаданные модели и режим доступа к ней.

## Г.4. Карточки элементов

Минимальный состав полей карточек:

- **Сущность**: имя; определение; бизнес-идентичность (КМД — 6.4); принадлежность домену; владелец семантики; статус определения (8.2).
- **Атрибут**: имя; домен либо семантический класс (7.4–7.5); обязательность; статус определения; для AS-IS — состояние соответствия каталогу.
- **Связь**: участники и роли; кардинальности (установленное значение либо статус неизвестности с основаниями и вопросом — 3.10); характер связи (для AS-IS — 9.6).
- **Бизнес-правило**: формулировка; вид (5.7); механизм контроля и состояние реализации (8.9).
- **Соответствие**: вид соответствия (8.3–8.7); стороны; тип; статус; основание.

## Г.5. Карточка утверждения

Ведётся для существенных утверждений (5.7). Поля:

- утверждение (ссылка на элемент и конкретную характеристику — не на элемент целиком);
- вид утверждения: определение понятия / бизнес-правило / описание реализации / наблюдение;
- отнесение к состоянию: AS-IS / TO-BE (наследование от версии модели — по умолчанию);
- характер изменения: добавлено / изменено / исключено / без изменения — с указанием базы сравнения (4.6);
- источники: множественно, с ролью (подтверждает / противоречит), контекстом и периодом действия;
- статус подтверждения: подтверждено / предположение / не установлено / противоречие источников (5.8);
- история смены статуса: основание, источник, дата (5.8).

## Г.6. Свидетельство

Свидетельство связывается с объектом подтверждения (10.1, [[Стандарт#^GEN-004|GEN-004]]). Поля:

| Поле | Содержание |
|---|---|
| Идентификатор | `EV-xxx` |
| Объект подтверждения | Утверждение / бизнес-правило / элемент модели / процедура / факт выполнения организационного требования |
| Тип | Протокол, отчёт о проверке, результат сверки, манифест выпуска, результат сравнения экспорта, экспертное заключение и др. |
| Содержание | Ссылка либо зафиксированный результат |
| Дата и исполнитель | Дата; исполнитель (роль/средство) |
| Связи | Записи результатов проверки (прил. А.8), карточки утверждений |

## Г.7. Масштаб ведения карточек

Карточки ведутся для **существенных утверждений** (5.7). Допускаются: наследование источников и контекста от модели или пакета; групповое подтверждение однотипных сведений. Отдельные записи обязательны для исключений, спорных и критичных утверждений. Полнота доказательств важнее количества оформленных карточек.
