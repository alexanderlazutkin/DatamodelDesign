# Приложение Л. Шаблоны рабочих артефактов

**Версия:** 0.3-в1 (волна 1 Д7, рабочая редакция стандарта 0.3). Статус — рабочий документ; формы минимальны по составу полей и расширяются без сокращения. Машиночитаемые формы вводятся по мере включения в реестр (3.11).

## Л.1. Паспорт модели

Состав полей — прил. Г.2 (не дублируется). Создаётся до начала работ (5.1).

## Л.2. Запись реестра вопросов (4.8)

| Поле | Содержание |
|---|---|
| Идентификатор | Стабильный ID записи |
| Формулировка | Вопрос/расхождение/несопоставленный элемент |
| Категория | Пробел документации / ограничение обследования / конфликтующая трактовка / недостаток реализации / предложение развития / расхождение либо несопоставленный элемент соответствий |
| Объект | Элемент модели / соответствие / процедура |
| Статус подтверждения | 5.8 (для вопросов о фактах) |
| Ответственный, срок | Роль и дата закрытия |
| Влияние на модель | Блокирующее / ограничивающее / не влияющее (10.9) |
| Итог | Решение, связь с записью решения (Л.3) |

Связь форм: Л.2 «Итог» → идентификатор записи решения (Л.3); Л.3 «Связи» → идентификаторы вопросов (Л.2). Отношение «вопрос → решение»: реестр вопросов (4.8, форма Л.2) и реестр решений по моделированию (8.1, форма Л.3) ведутся раздельно и не сливаются.

## Л.3. Запись решения (8.1)

| Поле | Содержание |
|---|---|
| Идентификатор | Стабильный ID записи |
| Принятое решение | Формулировка |
| Альтернативы | Рассмотренные варианты |
| Основание | Требование / источник / анализ |
| Автор, дата | Роль, дата принятия |
| Затронутые элементы | Ссылки на элементы моделей |
| Связи | Вопросы (Л.2), записи проверки, исключения (3.8) |

## Л.4. Пакет изменений (4.6)

| Поле | Содержание |
|---|---|
| Идентификатор, наименование | Стабильный ID |
| Базовая версия | Утверждённая версия-основание |
| Перечень изменений | Элемент; характер изменения (5.7) |
| Основание | Требование / инициатива |
| Результат проверки | Протокол проверки изменений (10.7) |
| Статус | Черновик / проверен / включён / отклонён |

## Л.5. Протокол проверки (10.11)

| Поле | Содержание |
|---|---|
| Объект и версия | Модель/комплект, версия, выпуск (манифест) |
| Применённые виды проверки | 10.1 (формальная, семантическая, структурная, межмодельная, экспертная, сценарная) |
| Результаты по видам | С записями по требованиям (прил. А.8) и свидетельствами (прил. Г.6) |
| Замечания | С классификацией (10.9) |
| Исключения | Действующие исключения (3.8) |
| Решение | Принято / принято с замечаниями / не принято (основания — 10.10) |
| Подписи | Участники по ролям (прил. К), дата |

## Л.6. Манифест выпуска

Схема и правила — прил. А.6; записи ведутся в реестре (`registry/releases/`).

## Л.7. План пилота

Структура полей плана пилота — по подготовительному черновику (Р-019, `wrk/development/Д4 План AS-IS-пилота.md`): требования пилотного выпуска, проверочные случаи с правилами изоляции тестовых копий, границы представительности, критерии приёмки, показатели трудоёмкости, три раздельных заключения. При передаче результатов внешнего пилота (Р-020) черновик используется как основа шаблона; поля, зависящие от объекта, заполняются по фактическим данным.

---

*Конец приложения Л. Формы артефактов, включаемых в реестр, переводятся в машиночитаемую форму по схемам реестра (прил. А).*
