## Л.7. План пилота

Структура полей плана пилота — по подготовительному черновику (Р-019, `wrk/development/Д4 План AS-IS-пилота.md`): требования пилотного выпуска, проверочные случаи с правилами изоляции тестовых копий, границы представительности, критерии приёмки, показатели трудоёмкости, три раздельных заключения. При передаче результатов внешнего пилота (Р-020) черновик используется как основа шаблона; поля, зависящие от объекта, заполняются по фактическим данным.

## Л.8. Карточка утверждения — форма ведения (5.7, Г.5; Р-054, К-19 — review/12)

Формальная фиксация существенных утверждений (дополняет карточку прил. Г.5, не заменяя её полей). Каждое утверждение записывается канонической формой:

| Поле | Содержание |
|---|---|
| Имя утверждения | «X RELATED TO Y» (связь) / «X IDENTIFICATION» (идентификация) / «X HAS ATTR» (атрибут) |
| Канонический текст | «Каждый X должен быть / может быть <имя связи> один и только один / один или много Y» — с обеих сторон для связей (2.8) |
| Вид утверждения, состояние, статус | По 5.7 (T-034, T-035, T-037) |
| Источник | Запись планировочного утверждения (Л.10) / интервью / документ (5.3) |

Правила ведения: утверждения редактируются для согласованности имён; сводка утверждений сверяется с матрицей «сущность–сущность» — выявляются пропущенные связи (в том числе «с другой стороны»); термины сущностей — имена существительные, канонические по словарю 2.1. Форма — рекомендованная (методическая), обязательные поля утверждения — по Г.5.

## Л.9. Чек-лист требований этапа (5.10; Р-054, К-12 — review/05)

Пять рубрик проверки требований этапа (используется при составлении условий приёмки 5.10 и листа О-1):

1. **Входы** — что запускает процесс/функцию (выход одного процесса — вход другого).
2. **Выходы** — результаты: отчёты, списки, завершённые функции (утверждение, проверка).
3. **Процессы** — действия, которые должны выполняться.
4. **Измеримые характеристики** — производительность, носители, объёмы.
5. **Контроль** — проверки и ограничения доступа.

Критерий завершённости: проектирование считается завершённым, когда требования чек-листа выполнены и подтверждены согласованными критериями.

## Л.10. Таксономия планировочных утверждений и таблица источников (5.3, 5.7; Р-054, К-18 — review/12)

Три уровня утверждений-источников (по 21 виду; уровни — ориентиры, вид может относиться к другому уровню):

| Уровень | Виды | Вопрос-классификатор (пример) |
|---|---|---|
| Стратегический | видение; миссия; допущение; сильные/слабые стороны; возможности; угрозы | «Что должно получиться в итоге?» / «Что мешает успеху?» |
| Тактический | цель; стратегия; критический фактор успеха; целевая задача (objective); политика; тактика; мероприятие (task) | «Что хотим достичь на уровне функции?» / «Что погубит проект при провале?» |
| Операционный | бизнес-событие; системное событие; системное требование; цель проектирования (objective); **бизнес-правило**; вопрос на разрешение; замысел системы (design goal) | «Какие отношения должны существовать, чтобы работа выполнялась упорядоченно?» (бизнес-правило) |

Таблица источников (где искать, 5.3): стратегические — стратегические планы, сайты, документы акционеров, прогнозы, бюджеты; тактические — бизнес-планы, заявки, отчёты о результатах, оргструктуры, должностные инструкции, аудиты; операционные — регламенты и руководства (что должно происходить), транзакционные файлы и отчёты (что происходило), пользовательские и справочные руководства, договоры. Внешние источники (стандарты отрасли, отраслевые модели данных, опубликованные модели типовых функций, планы похожих организаций) — вспомогательные.

Правила сбора (review/12): каждое утверждение проверяется на соответствие практике (а не только декларации); на ясность, непротиворечивость и проверяемость; на актуальность; фиксируется, что именно отражает — «как есть», «как должно быть» или «как будет» (T-035).
