# Приложение К. Матрица ответственности

**Версия:** 0.3-в1 (волна 1 Д7, рабочая редакция стандарта 0.3). Статус — **черновая схема**: ролевая структура и распределение полномочий зафиксированы; организационные назначения (исполнители, подразделения) — после ПВ-01; до назначения действует порядок плана разработки (4.1).

## К.1. Назначение

Матрица устанавливает распределение «роль × этап × артефакт» и полномочия на ключевые решения (4.1). Обозначения RACI: **R** — исполняет; **A** — утверждает/несёт ответственность; **C** — консультируется; **I** — информируется.

## К.2. Ролевая база (4.1)

| Роль | Зона ответственности |
|---|---|
| Владелец модели | Целостность и жизненный цикл модели; принятие результатов работ по модели |
| Владелец бизнес-семантики | Утверждение бизнес-семантики домена; подтверждение определений и правил |
| Разработчик модели | Разработка и самопроверка моделей (6.15, 7.17); метаданные |
| Архитектор данных | Архитектурные решения; разрешение конфликтов профилей и междоменных разногласий |
| Технический эксперт | Техническая осуществимость; сверка с реализацией |
| Эксперт по ИБ | Разметка ИОД (прил. И); профили публикации (11.10); согласование исключений в части ИБ |
| Ответственный за репозиторий и публикацию | Хранилище, статусы версий, комплекты публикации |
| Утверждающее лицо | Утверждение моделей и выпусков; принятие блокирующих рисков |

Совмещение ролей допустимо по решению владельца стандарта; факт независимой проверки нельзя заявлять, если её не было.

## К.3. RACI по этапам (4.2) — черновая схема [подтверждение — ПВ-01]

| Этап | Владелец модели | Владелец семантики | Разработчик | Архитектор данных | Технический эксперт | Эксперт ИБ | Отв. за репозиторий | Утверждающее лицо |
|---|---|---|---|---|---|---|---|---|
| 1. Постановка задачи | A | C | R | C | I | I | I | I |
| 2. Охват и основания | A | C | R | A | C | C | I | I |
| 3. Разработка КМД | C | A | R | C | C | C | I | I |
| 4. Согласование концептуальной семантики | C | A | R | C | I | I | I | C |
| 5. Разработка ЛМД | C | C | R | A | C | C | I | I |
| 6. Проверка моделей и соответствий | I | C | C | R | C | C | I | A |
| 7. Приёмка и публикация | C | I | I | C | I | C | R | A |
| 8. Сопровождение | A | C | C | C | C | I | R | I |

Двойная ответственность A на этапе 2 (владелец модели — за охват, архитектор данных — за профиль и границы систем) разрешается указанием объекта решения в плане работ (5.10).

## К.4. Полномочия на ключевые решения — черновая схема [подтверждение — ПВ-01]

| Решение | Уполномоченная роль | Основание |
|---|---|---|
| Утверждение бизнес-семантики | Владелец бизнес-семантики | 4.1 |
| Принятие архитектурных решений | Архитектор данных | 4.1 |
| Разрешение конфликтов профилей | Архитектор данных | 2.4 |
| Разрешение междоменных разногласий | Архитектор данных | 4.4 |
| Согласование исключений (3.8) | По уровню влияния: архитектор данных; для ИОД — совместно эксперт ИБ; [Заполняется: перечень согласующих] | 3.8 |
| Разрешение публикации | Ответственный за репозиторий; профили — по согласованию с экспертом ИБ | 11.10 |
| Смена статусов версий | Ответственный за репозиторий — по решению утверждающего лица | 11.9 |
| Включение изменений в корпоративные модели | Архитектор данных; согласование с владельцами затронутых доменов | 4.7 |
| Принятие риска остаточного вопроса | Блокирующего — утверждающее лицо; ограничивающего — владелец модели; не влияющего — разработчик с фиксацией | 10.9 |
| Решение о приёмке | Уполномоченный проверяющий / утверждающее лицо | 10.11 |
| Принятие исключений из перечня требований, не допускающих исключений | Не допускается | 3.8 |

## К.5. Ведение матрицы

Матрица ведётся в структурированном виде со ссылками на ID (3.11). Изменения полномочий — решение владельца стандарта (ПВ-01); организационные назначения (исполнители ролей) фиксируются в [Заполняется: реестр назначения ролей организации].

---

*Конец приложения К. До назначения ролей организации (ПВ-01) действует порядок плана разработки; черновой характер схемы отражён в «Контроле документа» стандарта.*
