# Правила оформления и навигации нормативного комплекта

**Версия:** 0.1, 2026-10-12 (Р-041 — требование интерактивной навигации установлено пользователем; инструменты `tools/nav.py`, `tools/build_docx.py`).
**Статус:** рабочий документ комплекта; оформительское требование уровня пользователя — действует до подтверждения владельцем (ПВ-01).
**Назначение:** единые правила ссылочной навигации markdown-документов комплекта (Obsidian) и сборки единого .docx с сохранением навигации. Нормативное содержание (формулировки требований, термины, модальности) этими правилами не изменяется.

## 1. Область действия

| Включено | Исключено |
|---|---|
| `Стандарт.md`, `Регламент AS-IS.md`, `appendices/*.md`, `registry/terms-draft.md` | YAML-реестр (`registry/requirements`, `asis`, `releases`) — машиночитаемая форма, ссылки не вводятся |
| Все правки оформления перечисленных документов | `wrk/development/*.md` (рабочий журнал — Р-xxx не являются целями навигации комплекта) |
| Сборка единого .docx (раздел 5) | Исходные документы `src/` (С01–С09 — внешние источники, на них ссылки не наводятся) |

## 2. Требование к ссылкам (markdown / Obsidian)

**НР-1. Ссылки интерактивны.** Отсылки к терминам, требованиям, процедурам, документам и пунктам комплекта оформляются wikilink-ссылками Obsidian: клик по ссылке открывает цель (файл, заголовок, строку таблицы, абзац).

**НР-2. Цели и якоря.**

| Цель | Файл | Якорь | Пример ссылки |
|---|---|---|---|
| Термин `T-xxx` | `terms-draft.md` | block-ID строки таблицы `^T-008` | `[[terms-draft#^T-008\|ИОД]]` |
| Требование `CDM/LDM/GEN-xxx` | `Стандарт.md` | block-ID абзаца формулировки `^LDM-040` | `[[Стандарт#^LDM-040\|LDM-040]]` |
| Процедура `PR-xxx` | `appendices/Ж …` | block-ID карточки `^PR-001` | `[[Ж Контрольные листы и процедуры приёмки#^PR-001\|PR-001]]` |
| Раздел Стандарта / Регламента | `Стандарт.md` / `Регламент AS-IS.md` | заголовок (текст) | `[[Стандарт#7.9. Справочные данные и классификаторы\|7.9]]` |
| Приложение / пункт прил. | `appendices/<буква> …` | заголовок (текст) | `[[И Профиль классификации ИОД#И.4. Минимальный объём для пилота\|прил. И.4]]` |
| Документ целиком | любой из комплекта | без якоря | `[[terms-draft\|словарь терминов]]` |

Правила якорей: block-ID совпадает с ID объекта (`^T-001`, `^LDM-046`, `^PR-009`) — ставится в конце абзаца формулировки (Стандарт, Ж) или последней ячейки строки таблицы (terms-draft); ID якорей не переиспользуются; удаление цели — только с перенаправлением ссылок.

**НР-3. Плотность.** Ссылкой оформляется **первое упоминание объекта в пределах раздела** (`##`); повторные упоминания в том же разделе остаются плоским текстом.

**НР-4. Не оформляются ссылками:** отсылки к внешним источникам С01–С09; записи рабочего журнала `Р-xxx` и `Q-*.x`; диапазоны (`LDM-040…046`, `4.1–4.11`); упоминания внутри таблиц-каталогов (реестр Ж.10, перечень приложений) и собственных строк-определений (self-link); текст внутри блоков кода и YAML.

**НР-5. Подпись ссылки сохраняет исходный текст** упоминания (например, `LDM-046`, `прил. И.4`) — оформление не меняет читаемость текста.

## 3. Инструменты и проверки

```
uv run python tools/nav.py anchors   # вставка/контроль block-ID (идемпотентно)
uv run python tools/nav.py linkify   # плоские отсылки -> wikilinks (первое упоминание в разделе; НР-4)
uv run python tools/nav.py check     # резолв всех ссылок и якорей; код != 0 — ошибка приёмки
```

`check` входит в состав проверок приёмки наравне с `registry_check.py`: неразрешимая ссылка, дубликат якоря или ссылка на удалённую цель — блокируют изменение. Тесты — `tests/test_nav.py`.

## 4. Порядок внесения изменений оформления

1. Правки оформления не меняют формулировки (дословность текст↔реестр сохраняется — проверка приёмки).
2. Массовые изменения оформления рецензированных документов выполняются инструментально (`nav.py`) с последующим `nav.py check` и прогоном полного набора тестов.
3. Рецензирование массовых правок контуром R — отдельным прогоном (std-0xx) по решению пользователя.

## 5. Единый .docx комплекта

**Требование:** комплект собирается в **один** .docx-файл со сквозной навигацией: внутренние ссылки работают как гиперссылки Word (Ctrl+клик) на закладки.

- Состав сборки: титульный лист → содержание → `Стандарт.md` → `Регламент AS-IS.md` → приложения А…Ф (по порядку букв) → `terms-draft.md` (глоссарий).
- Каждая wikilink-цель получает закладку: заголовки (разделы, пункты прил.), block-ID (требования, термины, процедуры). Ссылки становятся внутренними гиперссылками на закладки.
- Сборка: `uv run --with python-docx python tools/build_docx.py --out dist/Комплект_стандарта.docx`; артефакт — `dist/` (вне Git, пересобирается).
- Верификация: `build_docx.py --verify` — каждая внутренняя гиперссылка имеет закладку, каждая закладка достижима из содержания; код != 0 — ошибка сборки. Проверка навигации в Word/LibreOffice — офисным инструментарием (officecli).
- Стиль: заголовки — стандартные стили Word (Heading 1–4); основной текст — Times New Roman 12 пт, интервал 1,15; таблицы — Table Grid. Стиль оформительский, утверждается вместе с ПВ-01.
